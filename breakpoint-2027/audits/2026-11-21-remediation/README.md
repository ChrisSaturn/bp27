# Lighthouse remediation — completed in stages

Coordinated by the main agent with three subagents owning startup, HTTP delivery, and assets/CSS/script preparation. No software or package was installed. The same visual and interaction contract remains in force.

## Results

Lighthouse 13.5.0, private Brave/Chromium 157 window, Navigation/Performance only, Clear storage and default simulated profiles, with external device/network throttling disabled. Final mobile results use three runs on the identical final source; desktop is one run. These are local lab measurements and remain sensitive to hardware, power management, and host load. The baseline is the earlier single-run [original audit](../2026-11-21/README.md).

## Piece-by-piece work

| Stage | Owner | Change | Verification |
| --- | --- | --- | --- |

| JavaScript delivery | assets subagent | Conservative generated compact siblings, validated with existing Acorn at build time only | Raw token/comment/literal and AST equality; all script syntax checks; minification audit passes |
| Integration | main coordinator | Reviewed and integrated stages, validated server, browser, fallback, and repeated Lighthouse | Final results above and reports below |

The initial profile (`startup-before.cpuprofile`) at temporary 4× CPU throttling had main-thread self samples of makeInkNormal 332ms, makeNormal 216ms, film 86ms, getImageData 62ms, surface 60ms, difference 53ms, and normalize 45ms. The worker and combined profiles show the numeric kernels absent from the main thread. Shader source, mesh/map resolution, generated bytes, font rasterization, pixel-density limits, and animation curves remain unchanged.

The startup-only checkpoint was followed by one combined diagnostic run scoring 94/TBT 277ms. This prompted repeated final measurements and exposed the last full-resolution DOM wordmark in the hidden CSS fallback. That wordmark and the hidden ticket logo now use the smaller responsive assets; the final PNG master remains used by the material renderer. Intermediate reports are retained rather than selected as final results.

## Validation and maintenance

- All 12 authored/generated browser scripts passed syntax checks. Optional preparation is idempotent on the final files.
- Native numeric checks verified identical vertices, indices, foil normals, and full-resolution ink-normal output, including clamped image boundaries. Cooperative fallback uses the same helper.
- A temporary server with worker-src blocked loaded the mesh via cooperative fallback and opened/closed the ticket. The test tab and server were stopped afterward.
- Normal browser checks verified hover lift -12px/scale1.045, complete dice spin to -972°, opening/closing, keyboard selection to -1008°, immediate reduced-motion selection back to -972°, and cleared hover state. At 390×844 the mesh resized with no horizontal overflow. Forced WebGL context loss restored the visible CSS fallback; reload restored the mesh. No normal-preview browser errors were reported.
- The header retains its original 104.45px width and proportions. Only DOM logo delivery changes; full-resolution texture artwork is preserved.
- Previous native browser device/network/category/Console settings were restored; temporary profiling/throttling was removed. Local optimized server remains at http://127.0.0.1:5173/.
- See [the preparation guide](../../tools/README.md) after authored file edits. Serving the checked-in site needs no parser/build dependency. The optional compactor reused an existing installed Acorn copy; it was not copied into the project or installed.
- The Python HTTP cache/compression setup applies locally. A different hosting provider must configure equivalent headers/compression; this work does not publish or modify a remote deployment.
